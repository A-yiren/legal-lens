# 律瞳 LegalLens 产品介绍

> **基于 RAG 的律师专属 AI 案件分析平台**
>
> 版本 v0.1.0 | 2026 年 8 月 13 日
>
> 服务地址：https://ayiren.cn/legallens/

---

## 1. 产品概述

**律瞳 LegalLens** 是一款面向律师的 AI 辅助分析平台，**不训练任何模型**，完全基于检索增强生成（RAG）技术——从 26 部中国现行法律 + 30 个真实判例的私有知识库中精准检索相关法条和案号，再交给大语言模型（LLM）综合分析。

### 1.1 核心价值

- **可追溯**：每条观点强制带 `[n] 法名 第X条` 引用，点开直达官方法律法规库原文
- **可验证**：4 Agent 协同校验（焦点识别 / 法律分析 / **引用真实性核验** / 风险评估），幻觉引用自动剔除
- **专业**：法律分析对标真实判例和法律实务，不替代律师但能大幅提升效率
- **共享账号**：与律瞳同服务器上的 aipath 共享用户体系，1 个账号两边通用

### 1.2 适用场景

| 用户 | 典型场景 |
|------|----------|
| **执业律师** | 案情初步分析 / 案件类案检索 / 合同快速审查 |
| **企业法务** | 标准合同审查 / 法律风险点识别 |
| **法律科技** | 集成 RAG 法律检索能力 |

## 2. 核心功能

### 2.1 案件分析（4 Agent 协同）⭐

**输入**：案情经过（自然语言描述）
**输出**：多维度结构化分析 + 引用法条 + 官方源链接 + 原文跳转

**4 Agent 流水线**（约 60-90 秒）：

```
┌─────────────────────────────────────────────────────────────┐
│ 案情输入                                                    │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 1: 向量化检索 (Embedding + Qdrant 混合检索 + RRF 融合) │
│ 召回 top-20 法条，rerank 后送入 LLM                          │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 2 (并行) A1 焦点识别  +  A4 风险评估                    │
│   独立 LLM 调用，识别法律焦点和潜在风险点                    │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 3: A2 法律分析 (基于 A1 焦点 + 检索法条)               │
│ 输出结构化分析，每条观点带 [n] 引用编号                       │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 4: A3 引用真实性校验 ⭐                                 │
│ 逐字核对 [n] 引用是否真在召回文档中，标"幻觉"               │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ Step 5: 整合                                                │
│  - 过滤 A3 标"幻觉"的引用                                   │
│  - 引用去重 (按 law_name + article_no)                       │
│  - 重新编号 [1] [2] [3]                                     │
│  - 补全 source_url / publisher / law_status                 │
│  - 重新计算 confidence = 通过校验的引用比例                  │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 类案检索

**输入**：案情描述 + 可选筛选（案由 / 法院级别）
**输出**：从 30 个真实判例种子中检索最相似的 N 个（含案号 / 法院 / 引用法条 / 相似度）

**覆盖 8 大法律领域**：

| 领域 | 判例数 | 典型场景 |
|------|--------|----------|
| 消费者维权 | 2 | 网购纠纷 / 跨境电商 |
| 劳动纠纷 | 3 | 违法解除 / 竞业限制 / 平台用工 |
| 婚姻家庭 | 2 | 离婚房产 / 同居财产 |
| 公司治理 | 2 | 小股东保护 / 股权转让对赌 |
| 知识产权 | 1 | 软件著作权侵权 |
| 刑事 | 3 | 刷单诈骗 / 黑客入侵 / 商业秘密 |
| 交通 | 1 | 误工费 + 保险拒赔 |
| 其他民事 | 15 | 借款 / 居间 / 物业 / 医疗 / 高空抛物 / 教育 / 保险 / 抵押 / 婚庆 等 |

### 2.3 合同审查

**输入**：合同全文 + 合同类型（劳动合同/买卖/租赁/服务/综合）+ 审查立场（我方/对方/中立）
**输出**：5 大模块报告

| 模块 | 内容 |
|------|------|
| **顶部风险等级卡** | 高/中/低 + 风险数量 + 缺失数量 |
| **AI 综合分析** | 整体评价 + 重点条款 + 建议修改（多 Agent 校验） |
| **风险点** | 10+ 规则引擎扫描（违约金过高 / 显失公平 / 管辖约定等） |
| **缺失的必备条款** | 5 类合同各有一套必备条款模板 |
| **相关法条** | 5 条 RAG 检索（按合同类型 + 5 个法律关注点并行检索 + 去重） |

**RAG 检索去重优化**：5 个 query 并行检索（如"劳动合同 工资待遇"、"劳动合同 竞业限制"...），每 query 拉 6 条，去重后按 score 取前 5——确保 5 条跨法律、跨主题、互不重复。

### 2.4 知识库浏览

- 26 部中国现行法律（含官方源 URL / 发布机关 / 施行日期 / 状态）
- 30 个真实判例种子（事实/理由/判决三段结构化）
- 顶部搜索框 + 案由/来源/状态筛选
- 文档预览 modal（含法律全文 + 判例三段）

### 2.5 Obsidian 集成

- 配置本地 Obsidian vault 路径
- 一键导出案件分析为 Markdown 到 vault
- 实时同步监听（新增文件自动同步到律瞳）

## 4. 核心运行流程

### 4.1 用户认证流程

```
用户访问 https://ayiren.cn/legallens/
         ↓
  frontend/auth.js 检查 localStorage
         ↓
  ├─ 有 token ──→ 携带 Authorization: Bearer <jwt> 请求
  │                       ↓
  │               后端 decode_token → aipath_auth.get_user_by_id
  │                       ↓
  │               返用户信息 → 业务 API
  │
  └─ 无 token ──→ 跳转到 /pages/login.html
                       ↓
                  用户输入 username + password
                       ↓
                  POST /api/auth/login
                       ↓
                  aipath_auth.authenticate (读 aipath 的 career.db)
                       ↓
                  签发 JWT (HS256, 72h) → 存 localStorage
                       ↓
                  跳转到首页
```

### 4.2 案件分析请求处理流程

```
用户点"开始 AI 分析"
         ↓
POST /api/analyze {query, top_k=12}
         ↓
   ┌──────────────────────────────────────────────┐
   │ 1. RetrievalService.search                   │
   │    - Embedding (bge-small-zh-v1.5)            │
   │    - Qdrant 混合检索 (dense + sparse)        │
   │    - RRF 融合 → top-12                        │
   │    - (可选) Rerank                            │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 2. 多 Agent 协同 (agents.py)                  │
   │                                              │
   │    asyncio.gather(                            │
   │        A1 焦点识别 (LLM call 1),              │
   │        A4 风险评估 (LLM call 2)               │
   │    )                                         │
   │              ↓                                │
   │    A2 法律分析 (LLM call 3, 基于 A1 + 检索)  │
   │              ↓                                │
   │    A3 引用校验 (LLM call 4, 逐字核对)         │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 3. 整合输出                                  │
   │    - 过滤幻觉引用 (A3 标"幻觉"的)             │
   │    - 引用去重 (按 law_name + article_no)      │
   │    - 补全元数据 (source_url, publisher, ...)  │
   │    - 重新计算 confidence                      │
   │    - 重新编号 [1] [2] [3]                     │
   └──────────────────────────────────────────────┘
         ↓
返回 JSON 响应给前端
         ↓
UI 渲染（每条引用带 [n] 徽章 + 官方源链接 + 原文跳转）
```

### 4.3 合同审查请求处理流程

```
用户点"开始审查"
         ↓
POST /api/contract/review
{contract_text, contract_type, user_role}
         ↓
   ┌──────────────────────────────────────────────┐
   │ 1. _scan_risks: 规则引擎扫描                  │
   │    10+ 高风险模式 (关键词+正则)                │
   │    → 返回 risk_findings                       │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 2. _check_required_clauses: 必备条款检查       │
   │    按 contract_type 选模板 (general/labor/...) │
   │    → 返回 missing                            │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 3. _retrieve_legal_basis: RAG 检索            │
   │    5 个法律关注点 query (按合同类型)            │
   │    每 query 拉 6 条 → 共 30 条召回             │
   │    按 (law_name, article_no) 去重              │
   │    排序取前 5                                  │
   │    → 返回 legal_citations                     │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 4. _llm_analyze: LLM 综合分析                 │
   │    输入: 风险点 + 缺失条款 + 合同文本         │
   │    输出: overall_assessment / key_clauses /   │
   │           priority_modifications / potential_risks │
   └──────────────────────────────────────────────┘
         ↓
   ┌──────────────────────────────────────────────┐
   │ 5. 综合: 计算 risk_level + summary            │
   │    high:  >= 1 个 high 风险                   │
   │    medium: >= 1 个 medium 风险               │
   │    low: 其他                                  │
   └──────────────────────────────────────────────┘
         ↓
返回 JSON 响应给前端
```

### 4.4 类案检索请求处理流程

```
用户输入案情 + 筛选条件
         ↓
POST /api/cases/search {query, top_k, cause?, court_level?}
         ↓
   ┌──────────────────────────────────────────────┐
   │ case_retrieval.search_similar_cases           │
   │                                              │
   │ 1. Embedding                                 │
   │ 2. Qdrant legal_cases 集合检索               │
   │    (filter: cause, court_level)              │
   │ 3. 按 case_id 分组 (每个案件 3 chunks)        │
   │ 4. 每案件保留 score 最高的 chunk              │
   │ 5. 按 score 降序取 top_k                      │
   └──────────────────────────────────────────────┘
         ↓
返回 {query, total, results[]}
         ↓
前端渲染案件卡片：案号 / 法院 / 案由 / 引用法条 / 相似度
```
