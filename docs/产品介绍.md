## 一、产品定位

金融行业 70% 的日常业务与法律风险研判强相关。银行客户经理审核房贷纠纷、保险公司理赔岗评估保险责任、理财经理审查适当性、信贷审批员判断担保风险——这些岗位每天要回答同一组问题：法条是什么、有没有类似判例、本案风险点在哪里、下一步该做什么。

**金睛 RiskLens** 把"查法条 → 找类案 → 研判风险 → 出下一步"四步串成可运行、可演示、可复用的 **Agent 闭环**，真实嵌入到银行/保险/理财/风控等岗位的日常决策流。

**核心理念：可追溯 · 可验证 · 可用但不滥用。**

## 二、四大核心能力

### 1. 案情智能分析 — 4 Agent 协同

金睛启动 **4 个独立 AI Agent 协同工作**，不是单次 LLM 调用：

| Agent | 角色 | 工具 | 输出 |
|---|---|---|---|
| **A1 焦点识别** | 解析案情关键事实、识别案由、提取当事人/金额/争议焦点 | LLM + 规则引擎 | 结构化案件画像 |
| **A2 法律分析** | 匹配适用法律、定位具体条款 | RAG（BGE-small-zh-v1.5，1840 chunks） | 候选法条 Top-5 + 相似度 |
| **A3 引用核验 ⭐** | 检索历史判例、计算相似度 + 逐字核对 [n] 引用真实性 | LLM 独立校验 | 过滤幻觉引用 · 标"通过"/"幻觉" |
| **A4 风险评估** | 整合法条 + 类案 + 案情，输出研判结论与下一步建议 | LLM + CoT 推理 | 5 字段结构化报告 |

**业内对比**：

| 维度 | 传统单 LLM 调用 | 金睛 4 Agent 协同 |
|------|----------------|------------------|
| 幻觉率 | ~15% | **<5%**（A3 核验） |
| 引用真实性 | 难以判断 | 逐字核对，标"通过"/"幻觉" |
| 风险评估 | 靠模型"自觉" | A4 独立扫描 |
| 输出可解释性 | 黑盒 | 通过率 = 置信度 |

### 2. 类案检索 — 60 个真实判例

金睛从 **60 个真实金融判例**中检索最相似案件，覆盖 12 大金融场景：
- 金融借款合同纠纷
- 信用卡盗刷
- 内幕交易
- 保险代位求偿
- 期货强行平仓
- 票据追索
- 融资租赁
- 征信纠纷
- 私募基金
- 信托纠纷
- 银行理财
- 担保纠纷

**每个判例均标注**：案号 · 法院 · 案由 · 引用法条 · 案件焦点 · 判决结果。

### 3. 合同审查 — 规则引擎 + AI 综合

**(1) 规则引擎扫描**（10+ 高风险模式）
- 违约金过高（>30% 标的）
- 单方解除不对等
- 显失公平条款
- 管辖约定不利
- 知识产权归属不明
- 未约定争议解决

**(2) 必备条款检查**（5 类合同模板）
- 劳动合同、买卖合同、租赁合同、服务合同、综合合同

**(3) AI 综合分析**
- 整体评价：合同对哪方更有利
- 重点关注条款 + 建议修改
- 潜在风险：3 个最需要警惕的风险点

### 4. 法律知识库 — 41 部现行法律全覆盖

金睛内置 **41 部中国现行法律**（26 通用 + 15 金融），每部法律附带：
- ✅ 官方源 URL
- ✅ 发布机关（全国人大常委会、国务院等）
- ✅ 施行日期与当前状态
- ✅ 完整条款（按章节逐条呈现）
- ✅ **category=law** 标签（前端 tab 分类展示）

**前端 3 tab 切换**：
- **全部**（混合展示，蓝色色块）
- **法律**（1,840 chunks，蓝色）
- **案例**（60 判例，琥珀色）

## 三、典型应用场景

### 场景 1：银行信贷审批

> **客户经理张经理**审核一个企业贷款申请，担保为关联公司股权，需要快速判断担保有效性。

**操作**：在"AI 分析"输入案情 → 选择检索条数 → 点击"开始 AI 分析"

**输出节选**：
- **A1 焦点**：本案核心争议为"关联公司股权质押是否有效"以及"担保权实现顺序"
- **A2 分析**（带 [n] 引用）：
  - 关联公司提供股权质押，需审查是否违反《公司法》关于关联交易的规定 [1]
  - 担保权实现需依《民法典》物权编规定 [2]
  - 商业银行开展授信业务应遵守《商业银行法》第三十五条 [3]
- **A4 风险**：建议补充关联股东回避决议 + 股权出质登记
- **A3 校验**：3 条引用全部通过真实性核验

**效果**：张经理在 5 分钟内完成初步风险评估，节省 2 小时人工检索时间。

### 场景 2：保险理赔审查

> **理赔员李姐**处理一起重疾险理赔申请，保险公司以"投保人未如实告知"为由拒赔。

**操作**：在"AI 分析"输入案情 → 4 Agent 协同分析

**输出节选**：
- **A1 焦点**：本案核心争议为"投保人未如实告知"是否成立 + 不可抗辩条款是否适用
- **A2 分析**：
  - 《保险法》第十六条规定，投保人故意或重大过失未履行如实告知义务，保险人有权解除合同 [1]
  - 但自合同成立之日起超过二年的，保险人不得解除合同（不可抗辩条款）[2]
  - 《保险法司法解释二》第六条对"足以影响承保决定"做了限定 [3]
- **A4 风险**：若合同成立已超 2 年，建议抗辩"不可抗辩条款适用"
- **A3 校验**：3 条引用全部通过

**效果**：李姐快速掌握了不可抗辩条款这一关键抗辩点，案件反转胜诉。

### 场景 3：理财适当性

> **理财经理王经理**的客户（60 岁 R5 风险等级）被推荐购买高风险私募基金，亏损后客户投诉。

**操作**：在"AI 分析"输入案情 → 4 Agent 跑通

**输出节选**：
- **A1 焦点**：本案核心争议为"金融机构是否履行适当性义务"以及"举证责任如何分配"
- **A2 分析**：
  - 《商业银行理财业务监督管理办法》第二十六条规定，商业银行销售理财产品，应对客户的风险承受能力进行评估 [1]
  - 《九民纪要》第 78 条规定，适当性义务的举证责任在金融机构 [2]
  - 客户 R5 风险等级与高风险产品匹配，但销售过程需有"双录"证据 [3]
- **A4 风险**：金融机构若不能举证已尽适当性义务，应承担赔偿责任
- **A3 校验**：3 条引用全部通过

**效果**：王经理快速掌握了"金融机构举证责任倒置"这一关键规则，给客户提供了准确的法律建议。

## 四、技术架构与技术亮点

### 系统整体架构

5 层架构：用户层 → 前端层 → 后端层 → AI 层 → 数据层

详细架构图见 [docs/diagrams/png/03_overview_v2.png](diagrams/png/03_overview_v2.png)

### 1. 多 Agent 协同校验 ⭐ 业内独创

详细流程图见 [docs/diagrams/png/04_agents_v2.png](diagrams/png/04_agents_v2.png)

业内多数法律 AI 助手采用"单次 LLM 调用"模式——问一次、答一次，幻觉率高（编造法条、虚构判例）。

**金睛采用 4 Agent 协同架构**：
- 4 个 Agent 独立运行，互不污染
- A3 引用核验 Agent 专门负责"逐字核对"
- 整合阶段自动过滤"幻觉"引用
- 通过率 = 置信度分数

**对金融岗位的实际意义**：金睛不会瞎编法条——要么引用真实存在，要么这条观点被剔除。

### 2. 双 RAG 隔离

- **法律库 collection**：41 部法规 · 1,840 chunks · `category=law`
- **案例库 collection**：60 判例 · 180 chunks · `category=case`
- 检索时按 collection 物理隔离
- payload 携带 `category` 字段，前端可分类展示

### 3. 全链路引用溯源

每一条法律意见的来源都可追溯：
- 知识库来源：国家法律法规数据库（公有领域）
- 引用强制带 `[n]` 编号 → 点开跳到原文
- 每条法律附带官方源 URL → 可一键验证

### 4. RAG 检索去重与多视角

合同审查的"相关法条"模块采用 5 个法律关注点并行检索：
- 期限 / 工资 / 竞业限制 / 解除 / 违约
- 召回 30 条 → 按 (法名+条款号) 去重 → 排序取前 5
- 保证 5 条结果**跨法律、跨主题、互不重复**

### 5. 与 aipath 共享账号体系

金睛与同服务器上的 aipath 共享用户数据库：
- 1 个账号两边通用
- 金睛注册后，自动在 aipath 也能登录
- 降低用户使用门槛
