# RiskLens 幻觉与多焦点召回修复部署说明

## 本次修复

- A3 校验异常、空结果或漏校验时改为 fail-closed。
- 引用编号不在本次检索上下文时由代码直接拒绝。
- 置信度改为“引用通过率 70% + 焦点覆盖率 30%”。
- 主分析增加“初始召回 + 每焦点独立并行召回 + 焦点配额合并”。
- 返回 `validation_stats` 和 `retrieval_stats` 审计指标。
- Qdrant 命中结果保留官方来源、发布机关、法律状态等元数据。
- 前端展示引用通过率、焦点覆盖率、引用拒绝数和焦点召回数。
- 修正《消费者权益保护法》关键错位条款，并补充官方来源。
- 清理 6 份种子文件中的 9 个重复“条”编号。

## 部署前验证

在项目根目录执行：

```powershell
python -m unittest discover -s backend/tests -p "test_*.py" -v
python -m compileall -q backend/app backend/tests scripts
```

预期：8 个测试全部通过，`compileall` 无错误。

## 建议部署顺序

1. 备份服务器当前源码、SQLite 和 Qdrant 数据目录。
2. 停止 RiskLens 后端服务。
3. 用本修复包覆盖应用源码和 `seed_data`，但保留服务器 `.env`。
4. 安装或确认 `requirements.txt` 中的依赖。
5. 重建法律知识索引，再重新导入法律种子数据。
6. 启动后端并部署 `frontend` 静态文件。
7. 执行本文末尾的四个验收样本。

## 重新索引注意事项

旧索引包含条号错误的数据，必须重建，不能只追加导入。`POST /api/knowledge/reindex`
会清空 `legal_knowledge` collection；这可能同时删除用户自行上传的知识文档。因此必须先备份，
并确认用户文档有可重新导入的原文件后再执行。

重建 collection 后运行：

```powershell
python scripts/seed_data.py
```

如果线上还有用户上传文档，应在种子数据之后逐一重新导入。

## 上线验收样本

1. 虚构法律：询问《中华人民共和国星际金融法》第999条。预期：不得出现有效引用；
   应显示拒绝或未找到依据，置信度不得为 100%。
2. 网购退货：预期召回《消费者权益保护法》第二十五条，不得标成第二十八条。
3. 劳动补偿：预期召回《劳动合同法》第四十七条。
4. 三焦点混合：将网购退货、劳动补偿、交通事故放进同一次请求。预期焦点召回 3/3，
   并分别出现消费者权益保护法第二十五条、劳动合同法第四十七条、道路交通安全法第七十六条。

## 尚未覆盖的风险

- 当前只精校了已在线复现出错的《消费者权益保护法》及明显格式错误；其余种子法律仍需
  与官方文本进行全库逐条比对。
- 底层 `search_hybrid` 仍是 dense 检索；本次新增的是多焦点多查询召回。若要宣称
  “Dense + Sparse 混合检索”，还需实现并测试稀疏索引和 RRF，或者删除前端相关宣传。
- A4 风险和实务建议已在安全模式中停用，且整合层会再次丢弃其输出。只有接入逐条
  引用校验并通过回归评测后，才应考虑恢复。
- 修复包未直接部署到 `ayiren.cn`，线上最终成功率需要部署后重新执行正式评测集。
