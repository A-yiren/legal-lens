## 一、算法基本原理

### 1.1 算法名称

**律瞳法律案件智能分析算法**（简称"律瞳算法"）

### 1.2 算法类别

- **大类**：生成式 AI / 自然语言处理
- **子类**：检索增强生成（Retrieval-Augmented Generation, RAG）
- **不涉及**：人脸生成、语音合成、深度伪造

### 1.3 算法目标

为律师和法律工作者提供：
1. **案情智能分析**：基于用户输入的案情描述，识别法律焦点、检索相关法条、给出参考分析
2. **类案检索**：基于 RAG 召回相似真实判例，给出可参考的案号、法院、引用法条
3. **合同审查**：基于规则引擎 + RAG + LLM 识别合同风险点和缺失条款

### 1.4 技术架构

```
[用户输入案情]
    ↓
[Step 1] 向量化（Embedding: BAAI/bge-small-zh-v1.5）
    ↓
[Step 2] Qdrant 向量库检索（top_k = 12，混合检索 + RRF 融合）
    ↓
[Step 3] 多 Agent 协同（4 个 LLM 调用）：
  ├── A1 焦点识别 Agent（独立 LLM 调用）
  ├── A4 风险评估 Agent（与 A1 并行）
  ├── A2 法律分析 Agent（基于 A1 + 检索结果）
  └── A3 引用校验 Agent（逐字核对 [n] 引用，标幻觉）
    ↓
[Step 4] 整合输出（过滤幻觉引用、引用去重、补全元数据）
    ↓
[UI 渲染] 每条引用带：法名 / 条款号 / 官方源 URL / 原文跳转
```

### 1.5 关键算法模块

| 模块 | 算法 | 自训/外部 | 说明 |
|------|------|-----------|------|
| Embedding | bge-small-zh-v1.5 | 外部（BAAI 公开） | 100MB 中文向量模型 |
| 向量检索 | HNSW | Qdrant 内置 | 行业标准算法 |
| RRF 融合 | Reciprocal Rank Fusion | 自研（开源算法） | 混合检索融合 |
| LLM | MiniMax-Text-01 | 外部 API | 不自训 |
| 引用校验 | 规则 + LLM 提示工程 | 自研 | 多 Agent 协同 |
| 规则引擎 | 关键词 + 正则 | 自研 | 合同审查 10+ 规则 |

## 二、训练数据情况

### 2.1 模型训练数据

**律瞳不进行任何模型训练。** 本服务所有大语言模型能力均通过调用 MiniMax-Text-01 API 实现，不涉及自有训练数据。

### 2.2 知识库数据

律瞳的 RAG 知识库由两类数据构成：

**A. 法律文本知识库（26 部法律）**

| 数据来源 | 数量 | 性质 | 采集方式 |
|----------|------|------|----------|
| 法律法规 | 26 部 | 公开 | 手动抓取国家法律法规数据库（flk.npc.gov.cn）及全国人大、国务院相关网站 |

**采集时点**：2026 年 6 月
**采集人**：[填写实际采集人]
**数据结构**：
- 每部法律 200-700 个语义块（chunk）
- 块大小 500 字，重叠 50 字
- 携带元数据：法律名、条款号、官方源 URL、发布机关、施行日期、当前状态

**B. 类案判例知识库（30 个判例）**

| 数据来源 | 数量 | 性质 | 采集方式 |
|----------|------|------|----------|
| 公开判例摘要 | 30 个 | 公开 | 选取 8 大法律领域典型真实案号格式判例（案号、当事人、法院、引用法条） |

**特别说明**：30 个判例的**案号、法院、案由、引用法条均为真实公开格式**，但**案情细节经过改写以脱敏**。本服务不存储原始判决书全文。

### 2.3 用户输入数据

- **不持久化**：用户输入的案情描述不写入数据库
- **不用于训练**：不收集任何用户数据用于训练目的
- **临时处理**：案情仅在请求生命周期内处理
- **传输加密**：HTTPS / TLS 1.3

## 四、风险评估

### 4.1 内容安全风险

| 风险点 | 描述 | 严重度 | 缓解措施 |
|--------|------|--------|----------|
| **幻觉法条** | LLM 可能虚构不存在的法条 | 高 | A3 引用校验 Agent 逐字核对 + 引用必须来自检索召回 |
| **幻觉案号** | LLM 可能虚构判决书 | 高 | 案号仅从类案知识库召回，LLM 不生成新案号 |
| **错误解读** | 法条引用错位、张冠李戴 | 高 | 每条引用带 source_url，可一键跳原文核验 |
| **片面意见** | 仅给单方有利意见 | 中 | 显式中立立场 + 风险评估 Agent 平衡提示 |
| **过时信息** | 法律修订后未及时更新 | 中 | 知识库带 law_status 字段标注（现行/已修订/废止） |

### 4.2 数据安全风险

| 风险点 | 描述 | 严重度 | 缓解措施 |
|--------|------|--------|----------|
| **用户案情泄露** | 案情含当事人隐私 | 中 | 不持久化 + 不训练 + 传输 TLS 1.3 |
| **判例脱敏不足** | 真实当事人信息曝光 | 低 | 案情细节已改写，仅保留案号/法院/法条 |
| **服务器入侵** | 法律数据库被改 | 低 | 阿里云 ECS + 安全组 + SSH Key |

### 4.3 服务可用性风险

| 风险点 | 描述 | 严重度 | 缓解措施 |
|--------|------|--------|----------|
| **LLM 不可用** | MiniMax API 故障 | 中 | 单源依赖，必要时可快速切换（GPT-4 / Claude / Qwen） |
| **向量库丢失** | Qdrant 损坏 | 低 | 可重建（26 部法律 5 分钟内可重入库） |
| **并发能力** | 1.6G 内存服务器 | 中 | 单进程串行，必要时升级配置 |

### 4.4 法律责任风险

| 风险点 | 描述 | 严重度 | 缓解措施 |
|--------|------|--------|----------|
| **律师误用** | 律师直接用 AI 输出当法庭意见 | **高** | 顶部显著免责声明 + "不替代专业律师" |
| **当事人误用** | 普通用户自行诉讼 | 中 | 免责声明 + 推荐"咨询专业律师" |
| **未成年人使用** | 缺乏年龄限制 | 中 | 建议服务协议加 18+ 限制 |

## 五、风险防控措施

### 5.1 内容侧

1. **多 Agent 协同**：4 个独立 Agent 互相校验，幻觉引用自动剔除
2. **强制引用来源**：每条观点必须带 `[n] 法名 第X条`，不可凭空生成
3. **官方源跳转**：每条引用点击直达官方原文页（flk.npc.gov.cn / 政府网站）
4. **版本标识**：法条带"现行/已修订"状态标签，避免引用废止法
5. **置信度展示**：每条分析带 confidence 分数，引用通过率越低分越低

### 5.2 数据侧

1. **数据来源合法**：26 部法律全部来自政府公开网站
2. **判例脱敏**：30 个类案案情细节已改写
3. **用户数据不持久化**：不存储、不分析、不训练
4. **HTTPS 全程加密**

### 5.3 用户侧

1. **强制知情同意**：用户协议 + 隐私政策 + 首次访问弹窗
2. **免责声明前置**：每次输出顶部加"AI 分析仅供参考，不构成法律意见"
3. **专业建议引导**：结尾推荐"咨询当地执业律师"
4. **投诉举报渠道**：客服邮箱 + 站内反馈入口
